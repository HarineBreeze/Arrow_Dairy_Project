# 兑换码与积分商城总表（截至 v4.9.23）

> 兑换入口：设置 → 活动 → 兑换码。同一「用户 ID」（本机档案，见个人信息页 /
> 侧边栏）下，标注「限 1 次」的码兑换成功后写入 `redeemedCodes`，再次输入提示
> 「该兑换码已使用过」；无限次码不写记录，每次输入都会生效。
> 兑换码统一忽略大小写与前后空格。

## 用户 ID 规则

- 从 **10001** 起的纯数字顺序号，每份新档案递增 1；首次启动分配后固化到档案。
- 序号单独存于 `user_id_seq.json`（与档案分开），档案被删除 / 重建后仍接着发号，
  不会退回 10001；跨重启保持单调不减。
- v4.9.22 及以前的 `AYO-xxxx-xxxx` 随机 ID，升级后首次读档自动迁移为下一个顺序号。
- 侧边栏显示 `ID：<顺序号>`，个人信息页可点击复制。

## 实现位置

- 码表与发放逻辑：`lib/services/reward_service.dart`
  - `pointsCodes`：限 1 次的积分码
  - `unlimitedPointsCodes`：不限次数的加分码（不写 `redeemedCodes`）
  - `unlimitedDeductCodes`：不限次数的扣分码（不写 `redeemedCodes`，最低 0）
  - `badgeCodes`：身份牌码
- 兑换记录字段：`UserProfile.redeemedCodes`（`lib/models/user_profile.dart`）
- 用户 ID / 注册日：`UserProfile.userId` / `registeredAt`；
  顺序发号与持久化：`UserStorage.allocateUserId` / `user_id_seq.json`
- 身份牌样式：`lib/widgets/identity_badge.dart`

## 其它获取积分的途径

- 每日首次发布笔记：+20 积分（`RewardService.dailyWritePoints`）

### 限时 VIP 权益的时效规则

- 日卡与周卡共用同一个到期时间 `vipCardExpireAt`：**兑换时在原有剩余时间上累加**，
  不覆盖、不重置。已过期或从未购买时才从兑换时刻起算。
- 身份牌选择页的「剩余x天」按累计后的到期时间计算，随实际购买天数增加
  （例如 1 张日卡 + 1 张周卡 = 剩余 8 天）。
- 限时 VIP 不进 `ownedBadges`；到期后读档自动摘牌换回普通版。
- 「终身VIP」是独立身份牌（兑换码获得），永久有效，不受限时权益到期影响。
