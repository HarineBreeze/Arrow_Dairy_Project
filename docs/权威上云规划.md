# 阿尤日记 AyoDiray — 权威上云规划

> 制定时间：2026-11-27　｜　基线版本：v5.0.7+165（纯离线单机）
> 默认方案：**数据加密同步上云 + 全套合规资质 + 阿里云（腾讯云备选）**；先按「免费同步」设计，文末标注一旦收费的追加要求。

---

## 0. 上云带来的根本变化

| 维度 | 当前（离线） | 上云后 |
|---|---|---|
| 是否联网 | 无 INTERNET 权限 | 必须加 INTERNET 权限，走 HTTPS |
| ICP 备案 | 只需 APP 备案 | **APP 备案 + 域名 ICP 备案都要**（服务器在大陆） |
| 等级保护 | 不需要 | **等保二级起步**（涉及大量公民个人信息），公安备案 30 日内 |
| 个人信息 | 全存本地 | 涉及收集/存储/传输个人敏感信息（日记、资产），受《个人信息保护法》全流程约束 |
| 隐私政策 | 简单声明即可 | 必须补全：收集清单、目的、存储期限、加密措施、用户删除权、泄露 72 小时报告 |
| 收费 | 无真实交易 | 若开会员订阅/云容量收费 → **需 ICP 经营许可证**（见 §5） |

> ⚠️ 关键认知（官方口径）：**「上了阿里云 ≠ 合规」**。云厂商只负责机房、虚拟化、网络边界等底层安全（云平台侧）；你作为租户，必须自行负责应用系统、数据库安全、账号权限、数据脱敏加密、漏洞修复、行为审计（租户侧）。等保测评时这部分不合格会被直接判定不通过。

## 1. 权威资质清单（APP 外，必须办）

### 1.1 基础三件套
- [ ] **域名**：注册一个自有域名（如 `ayodiray.com`），用于 API 和隐私政策页。
- [ ] **域名 ICP 备案**：通过云服务商（阿里云/腾讯云）提交，服务器在大陆即强制，5-20 工作日；备案主体必须与 APP 备案、软著、开发者账号一致。
- [ ] **APP 备案**：已有规划见上架清单；上云后如新增联网功能，若功能描述变化需评估是否变更备案。

### 1.2 等级保护（等保 2.0）
- [ ] **定级**：一般业务系统定二级；涉及大量公民个人信息或核心业务数据定三级。日记 App 建议按**二级**起步，若用户量大再升三级。编制《信息系统定级报告》并专家评审。
- [ ] **公安备案**：定级后 30 日内向所在地市级以上公安机关网安部门提交备案材料，取得《信息系统安全等级保护备案证明》。
- [ ] **安全建设整改**：按等保 2.0 要求加固——身份鉴别、访问控制、安全审计（日志留存 ≥ 6 个月）、数据完整性与保密性、备份恢复。
- [ ] **等级测评**：委托公安部认可的第三方测评机构测评，结论分"符合/基本符合/不符合"。**二级建议每 2 年复测，三级每年至少一次**。
- [ ] 注意 2026 年新规：GA/T 2380-2026《网络安全等级保护数据安全基本要求》已实施，等保进入「数据 + 系统」双维度测评，数据分类分级台账、敏感信息传输加密、访问审计是硬指标。

### 1.3 个人信息保护合规（《个人信息保护法》/《数据安全法》）
- [ ] **数据分类分级台账**：把日记、资产、身份档案等列为敏感数据，建立数据资产清单（类别、级别、位置、责任人）。
- [ ] **PIPIA**：处理敏感个人信息前做个人信息保护影响评估，留存书面记录。
- [ ] **明示同意 + 最小必要**：收集前弹窗告知，只收必需字段；查询/更正/删除渠道齐备。
- [ ] **泄露应急**：建立 72 小时内向主管部门报告的机制与流程。
- [ ] **测试环境脱敏**：开发/测试禁用真实用户数据，敏感字段去标识化。

## 2. 云上技术架构（APP 内 + 后端）

### 2.1 推荐架构（阿里云为例，腾讯云对应产品见括号）
| 层 | 选型 | 说明 |
|---|---|---|
| 接入 | API 网关 / SLB | 统一 HTTPS 入口，TLS 1.2+ 强制 |
| 计算 | 轻量应用服务器 / ECS（腾讯云 Lighthouse/CVM） | 起步够用，按量扩容 |
| 数据库 | RDS MySQL / PostgreSQL（腾讯云 CDB） | 开启透明加密、自动备份、审计日志 |
| 对象存储 | OSS（腾讯云 COS） | 存图片/附件，私有读写 + 服务端加密 |
| 密钥管理 | KMS（腾讯云 KMS） | 托管密钥，禁用硬编码密钥 |
| 日志审计 | SLS 日志服务（腾讯云 CLS） | 留存 ≥ 6 个月，满足等保审计 |
| WAF / 安全 | 云 WAF + 安全中心 | 防注入、防越权，满足等保三级要求 |

### 2.2 数据安全设计（日记是敏感档案，重点）
- [ ] **端到端加密优先**：日记正文在**客户端本地加密后再上传**，密钥由用户密码派生，服务端只存密文——即使服务端泄露也不会暴露内容。这是日记类 App 最权威的隐私姿态。
- [ ] **传输加密**：全链路 HTTPS，禁明文；敏感字段二次加密。
- [ ] **存储加密**：数据库透明加密 + OSS 服务端加密；不以明文出现在数据库、日志、备份中。
- [ ] **访问审计**：谁在何时访问/导出/修改/删除，全量留痕 ≥ 6 个月；限制批量导出。
- [ ] **备份恢复**：自动备份 + 跨可用区容灾，定期演练恢复。

### 2.3 APP 端改造
- [ ] 增加 INTERNET 权限，网络层统一 HTTPS + 证书校验。
- [ ] 登录/账号体系：从无账号变为有账号（手机号或邮箱），需配套验证码、**账号注销入口**（《个人信息保护法》强制）。
- [ ] 同步模块：增量同步 + 冲突解决 + 离线队列（断网继续用，联网补传）。
- [ ] 隐私政策升级：联网后重写，加入收集清单、跨境说明（如有）、删除权入口。
- [ ] 首次启动弹窗同意 + 权限说明，与上架清单 §1 一致。

## 3. 分阶段路线图（建议 4-6 个月）

| 阶段 | 事项 | 周期 |
|---|---|---|
| **P0 立项（T-120）** | 确认主体、注册域名、云厂商选型、确定免费/收费模式 | 1-2 周 |
| **P1 资质并行（T-120～T-60）** | 域名 ICP 备案、软著（若上架未办）、APP 备案变更评估 | 1-2 月 |
| **P2 开发（T-90～T-30）** | 后端搭建、APP 联网改造、端到端加密、隐私政策升级 | 4-8 周 |
| **P3 等保（T-60～T-15）** | 定级、公安备案、安全整改、等级测评 | 1-2 月 |
| **P4 提审（T-15～T）** | 各商店更新版本提审、上架后 30 日内完成公安备案 | 2-4 周 |

> 关键路径：ICP 备案与等保周期最长且可并行，必须 earliest start；端到端加密设计要在开发前定好，否则返工成本极高。

## 5. 一旦收费：追加要求

> 只要用户付费后才能用核心功能或内容（会员订阅、云容量、付费解锁），即属**经营性互联网信息服务**。

- [ ] **ICP 经营许可证**（B25 类）：企业主体、内资、注册资本 ≥ 100 万、3 名在职人员社保、域名已 ICP 备案，有效期 5 年，由省通信管理局审批。无证的处罚：没收违法所得 + 3-5 倍罚款，无违法所得罚 10-100 万，情节严重关站。
- [ ] 支付合规：微信/支付宝商户资质，虚拟商品走合规支付通道。
- [ ] iOS 端：数字商品必须走 IAP（苹果抽成），定价策略需单独设计。
- [ ] 广告盈利：同样触发 ICP 许可证要求。

---

## 6. 不用做的（避免浪费）

- ❌ EDI 许可证：只有引入第三方商家入驻、在线交易撮合才需要；纯自有同步服务不涉及。
- ❌ 数据出境安全评估：只要服务器和用户都在大陆、不向境外传输，不需要。
- ❌ 网络文化经营许可证 / 视听许可证 / 游戏版号：非相关业务。

---

## 7. 一句话总结

> 权威上云 = **域名 ICP 备案 + 等保二级 + 个人信息保护合规** 三张"身份证"，技术上以**端到端加密**护住日记隐私，架构上用云厂商的 RDS/OSS/KMS/日志服务兜底租户侧责任。若开收费，再加 **ICP 经营许可证**。软著、备案、等保都可并行启动，越早越好。
