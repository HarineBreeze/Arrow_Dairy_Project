# 矢量日记 · 图标设计规范（细线方案 Fine）

> 本文件是 `lib/widgets/app_icons.dart` 的配套说明。
> **以后新增任何按钮图标，一律按本规范设计，不再使用 Material `Icons.*`。**

---

## 1. 为什么不再用 Material Icons

Material 图标是「实心 + 粗线 + 尖锐转角」的混排风格，放在浅蓝底、圆角卡片、
细字重的界面上有三个具体问题：

| 问题 | 具体表现 |
| --- | --- |
| 笔画偏重 | Material 线宽等效 2.0，和 15px 细字重的正文字重不匹配，图标抢视线 |
| 转角尖利 | 尖角在小尺寸下会糊成一团小黑点，缩放后不干净 |
| 风格混杂 | 同一个页面里会出现描边图标（outlined）和实心图标（filled）并存 |

细线方案把它们统一成一种笔画：**等粗线 + 圆头端点 + 圆角转角**。

---

## 2. 几何规范（硬性）

| 项 | 值 | 说明 |
| --- | --- | --- |
| 画布 | **24 × 24** | 所有路径坐标都在这个网格上 |
| 安全区 | **20 × 20** | 主体不得超出，四周恒定留 2px 呼吸 |
| 线宽 | **1.6** | 唯一允许的基准线宽 |
| 端点 | **圆头** `StrokeCap.round` | 不允许平头或方头 |
| 转角 | **圆角** `StrokeJoin.round` | 不允许尖角 |
| 主体尺寸 | 18–20 | 列表 / 导航图标视觉重量约 18×18，独立大图标可到 20×20 |

### 2.1 小尺寸补偿

16px 及以下自动把线宽提到 **1.8**。原因：线宽不随尺寸等比缩，
24px 下 1.6px 映射到 16px 只有 1.07 物理像素，抗锯齿会把线拉成灰雾。

### 2.2 走向限制

只允许 **0° / 45° / 90°** 三种走向。斜线必须是正 45°，
不允许 30°、60° 这类「看起来差不多」的角度 —— 它们在 16px 下会抖。

---

## 3. 造型规范

1. **一个图标最多 3 个部件**：一个主体 + 至多两个附属（如放大镜的柄、日历的两条挂钩）。
   超过 3 个部件在 16px 下必然糊。
2. **部件间隙 ≥ 2px**：并且是**跨 90° 方向的间隙**。例如放大镜的柄，必须与镜圈正交相接，
   而不是写成同心弧。
3. **闭合形状内轮廓离外轮廓 ≥ 2px**：否则描边会粘成实心块。
4. **不做粗细变化**：不允许「主体粗、细节细」，全图一种笔画。
5. **不加尖角、不加装饰性小点**：需要表达「点」时（如列表圆点），
   用 `M5.5 7v.1` 这种 0 长度 + 圆头端点的写法，得到一个直径 1.6 的圆点。

---

## 4. 成对图标规范

开关类、状态类图标必须成对设计，且**只允许一处不同**，其余部分逐字符一致：

| 成对 | 唯一差异 |
| --- | --- |
| `lock` / `unlock` | 锁梁是否开口 |
| `eyeOn` / `eyeOff` | 是否多一道 45° 斜线 |
| `pin` / `pinOn` | 针杆是否加粗实心 |
| `chevU` / `chevD` / `chevL` / `chevR` | 仅方向 |
| `arrowUp` / `arrowDn` | 仅方向 |

**为什么强制逐字符一致**：保持一致后，切换状态时只有「那一处」发生视觉变化，
用户的眼睛能立刻定位到变化点。如果两个图标是分别画的，即使看上去一样，
切换时也会出现整体「跳动」的错觉。

测试里对这一点有硬断言（`test/app_icons_test.dart` 的「成对一致性」组）。

## 5. 路径写法约定

### 5.1 支持的指令

`M m L l H h V v C c S s Q q T t A a Z z`

解析器对不认识的指令会**抛异常**，不会静默跳过。
（静默跳过会把整段路径变成空路径，画面上只表现为「图标没显示」，极难排查。）

### 5.2 `|` 分段：表达「实心的一笔」

一条路径里可以用 `|fill` 切成两段：

```
'钉头路径|fill 针杆路径'
```

- 前半段：按 1.6 描边
- 后半段：按 2.6 描边（等效实心）

用途是图钉的针杆、开关的填充块这类「细长实心」元素。
**不要用 `fill` 填充细长形状** —— 面积过小时 `Path.getBounds()` 会退化为空，
渲染出来什么都没有。

### 5.3 紧凑写法

允许省略空格：`a6 6 0 1 0-12 0` 里的 `0-12` 会被正确拆成 flag `0` 和数字 `-12`。
但为了可读性，**建议在坐标之间保留空格**。

## 6. 新增图标的流程

```dart
// 1. 在 AppIcons 里加常量，按分组放在对应区块
static const String wifi =
    'M4 9.4a12 12 0 0 1 16 0 M7.4 12.8a7.2 7.2 0 0 1 9.2 0 M12 16.6v.1';

// 2. 加进 all 映射表（否则覆盖率测试拿不到它）
'all': wifi,

// 3. 用 AppIcon 渲染，不要用 Icon
AppIcon(AppIcons.wifi, size: 22, color: Color(0xFF2A3B52)),
```

### 6.1 提交前自检清单

- [ ] 画布 24×24，主体在 20×20 内
- [ ] 线宽 1.6（小尺寸 1.8 由组件自动处理，不要手动改）
- [ ] 没有 30°/60° 斜线
- [ ] 部件数 ≤ 3
- [ ] 间隙 ≥ 2px
- [ ] 如果是成对图标，另一半也已同步改好，且只差一处
- [ ] `flutter test test/app_icons_test.dart` 通过（会自动检查越界、退化、圆形失真）
